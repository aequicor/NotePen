# Физическое перелистывание в reader-mode

Reader-mode использует `PageTransition.BOOK` как физический page-curl слой поверх существующей построчной пагинации. Важно: пагинация остаётся источником истины (`ReaderPagination` и `PagedReflowContent`), а curl работает только с frozen snapshots текущей/соседней страницы, чтобы не деформировать live Compose-дерево текста, выделений и заметок.

Источник истины: `reflow/impl/src/commonMain/kotlin/ru/kyamshanov/notepen/reflow/ui/bookcurl/BookCurlPhysics.kt` считает XPBD/PBD-подобную сетку листа, локальный grip, gesture wind/flutter и lighting; `BookCurlRenderer.*.kt` рисует mesh платформенно (`drawBitmapMesh` на Android, Skia `drawVertices` с texture coordinates на Desktop). `BookCurlOverlay.kt` отдельно проявляет target page как подложку ближе к завершению curl, а native renderer деформирует только текущий лист. Подключение к reader находится в `PagedReflowContent` внутри `ReflowReader.kt`.

Инварианты: public API не меняется, `ReaderSettings.pageTransition = BOOK` выбирает новый путь автоматически; при reduced motion, заблокированном выделении или неподдержанном renderer надо оставаться на безопасном fallback. Curl нельзя запускать без frozen snapshots текущей и целевой страницы: иначе overlay не появится, а отпускание жеста будет выглядеть как резкая замена страницы. `gripY` фиксируется в начале жеста/анимации и не должен плавать по мере движения пальца, иначе лист выглядит резиновым. Фаза curl важна для физики: live drag передаётся как `Dragging`, отпускание с commit как `Completing`, недолист/отмена как `Returning`, иначе wind/flutter не затухают после release. Соседнюю страницу нельзя рисовать как текстуру деформируемого листа: на Desktop это выглядело как резкое затемнение и подмена страницы, поэтому target page проявляется отдельной подложкой, а cast/rim shadows ограничены областью поднятой mesh-сетки. В `twoPageSpread` деформируется только внешняя половина разворота: forward берёт правую текущую половину и уводит её через центральный корешок, а под ней в правом слоте рисуется правая половина target-spread; backward делает симметрично с левой текущей и левой target-половиной. Это digital-spread правило, потому что после commit выполняется `scrollToPage(target spread)` и подложка должна совпадать с финальным состоянием pager. Target snapshot нельзя рисовать целиком поверх reader, иначе за листом появляется не та страница. Bitmap texture нельзя умножать на vertex colors в `drawBitmapMesh`/`drawVertices`, иначе Android выбеливает текст; лист должен иметь цельную paper-base по внешнему контуру mesh, а не cell-by-cell paper paths, иначе Android показывает сегменты сетки. Renderer дополнительно клипует bitmap страницы по контуру листа как readability pass: если platform mesh сильно схлопнулся на больших progress, лист не должен становиться пустой бежевой формой. На Android все bitmap для crop/mesh переводятся в software `ARGB_8888`, потому что software Canvas падает на hardware bitmap. Статические mesh buffers (`textureCoordinates`, `triangleIndices`) кешируются в `BookCurlOverlay`; не переносить их генерацию обратно в platform draw, иначе desktop curl снова начнёт аллоцировать крупные массивы на каждый кадр.

Проверка: `./gradlew :reflow:impl:jvmTest`, `./gradlew :reflow:impl:compileAndroidMain`. `BookCurlRendererDesktopTest` рендерит synthetic curl frame и overlay-composite frame: базовый свет плоской бумаги должен оставаться почти белым, тени должны быть локальными, target page не должен проявляться до commit window, а renderer обязан рисовать видимую бумажную поверхность даже при прозрачной texture. Этот тест также пишет preview PNG в `reflow/impl/build/bookcurl-preview/` (`curl-*` и `overlay-*`) для ручного просмотра формы листа, soft shadow и плавного reveal. `ReaderBookCurlGestureTest` прогоняет headless desktop drag по реальному `ReflowReader` в `PageTransition.BOOK`: проверяет отсутствие глобального затемнения в gesture frame, spring-back при недолисте, commit после достаточного перелистывания, fling ниже progress-threshold и commit в `twoPageSpread`. Ручная проверка всё ещё нужна для субъективной плавности в живом desktop-окне, потому что headless canvas не доказывает perceived frame pacing.
